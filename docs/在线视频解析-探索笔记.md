# 在线素材获取 · 探索笔记

> 分支:`feature/online-ingest`
> 目标:给一个网址,拿到可以进流水线的本地媒体文件。
> 状态:四条策略已实现并跑通(含真实 HTTP 下载测试),尚未在各大平台的真实链接上验证。

---

## 一、先把问题分清楚

「解析在线视频」听起来是一件事,实际上是**难度差三个数量级的五件事**:

| # | 场景 | 技术难度 | 稳定性 | 合规风险 |
|---|---|---|---|---|
| 1 | 媒体直链(`.mp3` / `.mp4`) | 极低 | 永久稳定 | 无 |
| 2 | 播客 RSS 订阅源 | 低 | 永久稳定 | 无(设计上就供下载) |
| 3 | 网页里暴露了地址(`<video>`、`og:video`、JSON-LD) | 低 | 中(改版即失效) | 低 |
| 4 | HLS 分片流(`.m3u8`) | 中(需 ffmpeg 合流) | 中 | 视站点而定 |
| 5 | 播放器运行时动态取址、带签名/风控 | 高 | 差(常年对抗) | **高** |

**结论:1-4 值得自己做,5 不值得。** 第 5 类是一场永无止境的军备竞赛——参数会变、
签名会变、风控会升级,自建方案的维护成本远超收益,而这正是 yt-dlp 这类项目
用几百个站点适配器和高频更新在解决的问题。所以本分支的策略是:
**1-4 自己实现,5 委托给用户自行安装的 yt-dlp,并把合规判断交还给用户。**

## 二、已实现的方案

`teco/ingest.py` 按「越干净越优先」的顺序尝试:

```
网址
 ├─ 后缀是媒体格式?          → 直接流式下载
 ├─ 响应头是 audio/* video/*? → 直接流式下载
 ├─ 是 RSS/Atom?             → 解析 enclosure,按期选择后下载
 ├─ 是网页?                  → 提取候选地址,按可靠度依次尝试
 │    ① og:video / twitter:player:stream   ← 站点自己声明的,最可靠
 │    ② <video>/<audio>/<source> 的 src
 │    ③ JSON-LD 的 contentUrl
 │    ④ 正文里出现的 .mp4/.mp3 直链
 │    ⑤ .m3u8 → 交给 ffmpeg 合流
 └─ 都不行                    → 提示可自行安装 yt-dlp 兜底
```

### 几个刻意的设计决定

**先分析,后下载。** `fetch.py <网址>` 默认只列出找到了什么,加 `--download` 才真的下。
面对一个不确定的网址,盲下一个 500MB 的文件是很糟的体验;先看清楚再决定,
也让用户对「这东西到底从哪来的」有掌控感。

**播客单独作为一条路径。** 播客的 `<enclosure>` 本来就是给客户端下载的,
这是所有来源里最正当、最稳定的一类,而且**内容形态恰好最适合本项目**——
两个人自然对话、有口误和笑声,正是 vlog 学习法要的那种语料。
所以它不是「顺便支持一下」,而是**推荐的首选来源**。

**yt-dlp 只委托,不捆绑。** 不写进 `requirements.txt`、不自动安装、不代为决定。
用户装了就能用,没装就给一句说明。是否使用、用在哪些站点,由使用者自行判断
并承担相应的服务条款与版权责任。

**体积上限与流式写盘。** 单文件 800MB 上限,边下边校验,超限立即中止并删除半成品。
防的是误把一个大文件或一个死循环流当成素材抓下来。

## 三、合规:这一节比技术更重要

对当前用途(家人自己学英语)来说,这些基本不构成问题。但这个项目后面可能
产品化,所以现在就要把边界想清楚:

**技术上能取到 ≠ 可以取。** 本模块只取回**公开可访问**的地址,不绕过付费墙、
不绕过登录态、不碰 DRM。这条线不能越——越过去性质就变了。

**自用与分发是两件事。** 家人下载一段视频自己学习,和把这些内容做成产品给别人看,
在法律上完全不是一回事。参考产品(那个小红书上的网站)正是踩在这条线上:
它搬运了大量海外博主的 vlog 并加了自己的水印,一旦商业化,这是最大的隐患。

**产品化的三条可行路线**(按风险从低到高):

1. **UGC 模式**——用户自带素材,平台只提供加工工具。风险最低,而且我们的流水线
   天然就是这个形态。**推荐**。
2. **授权/开放素材**——CC 协议内容、公共领域素材、与创作者签约。干净但成本高。
3. **自制内容**——自己拍或请人录。最干净,最慢。

**不推荐**:搬运他人内容再商业化。技术上最省事,法律上最脆弱。

## 四、验证情况

`tests/test_ingest.py` —— 19 项离线测试全通过,覆盖:直链判定、文件名清洗、
RSS/Atom 解析、相对路径补全、JSON-LD 转义还原、候选去重、异常输入。

另用本地 HTTP 服务做了端到端验证:直链分析、订阅源列期、网页候选提取、
真实下载并落盘,四条路径均通过。

**尚未验证**:各大视频平台的真实链接。原因是开发环境的网络受限,而且不同平台
差异极大——这部分需要在你本机拿真实网址试,再按结果补适配。

## 六、用法

```bash
python fetch.py <网址>                    # 只分析,看看里面有什么
python fetch.py <网址> --download         # 确认后下载
python fetch.py <订阅源> --index 2 --download   # 下订阅源里的第 3 期

python process.py --url <网址> --title "第1期"   # 取素材 + 直接做成学习材料
```
