# EchoLab · 视频转英语学习材料流水线

一条命令,把任意英文视频变成精读级学习材料:语义群对齐的双语字幕、IPA 音标、
六类知识点卡片(带考级标签),再配一个为「影子跟读 / 回音练习法」设计的播放器。

设计目标是**家人自己就能用**——加视频、学、收藏,全程不需要你在场。

---

## 一、它做了什么

```
视频 ─▶ 音频 ─▶ 语音识别(词级时间戳)─▶ 语义群切分 ─▶ 翻译 ─▶ IPA
                                                        └─▶ 知识点卡片 ─▶ 校验 ─▶ data.json
```

关键点在**语义群切分**:参考产品是作者手工把字幕截成完整语义群(这是三个月里最贵的
那部分工作),这里改由模型按语义切、再用词级时间戳映射回时间轴,几秒钟完成。

另外两个刻意的工程决策:

- **模型输出的是词的下标,不是重写后的文本。** 让模型改写文本就无法可靠对回时间轴了
  (会漏词、改标点、合并缩写);输出下标则可以被程序严格校验和自动修复,时间轴永远准。
- **每张卡片都要回原文验证才留下。** 模型偶尔会"想起"一个原文没有的表达,
  而学习工具里出现凭空捏造的知识点是不可接受的。校验做了词干还原,
  所以 `take off` 能对上原文的 `took it off`,但 `break the ice` 这种没出现过的会被剔除。

演示的音频是本机合成的机器音,只为让你先看清学习体验长什么样。

## 二点五、词卡分成「单词」和「语块」

播放器右侧是四个标签:**字幕 / 单词 / 语块 / 收藏**。

「语块」就是 lexical chunks,涵盖短语、短语动词、搭配、口语句式、话语标记
这五类多词表达。单独拆出来是因为两者的练法根本不同:单词是一个个记的,
语块得整块内化——把 `on the same page` 拆成三个词去背毫无意义。

分开还有个很实际的理由:抽取本身就偏向语块(课本里学不到 "I was just like…"
这种东西),实测一期 133 张卡里 114 张是语块,混在同一张列表里,剩下那 19 个
单词根本翻不到。

## 三、正式使用

### 1. 装环境(一次性)

```bash
pip install -r requirements.txt
```

**两个外部程序,都不是硬性必需:**

| 程序 | 缺了会怎样 | 建议 |
|---|---|---|
| ffmpeg | 不影响。识别会改用内置解码器(PyAV)直接读原文件,只是没有封面图 | 装了更稳,能处理更多冷门格式 |
| espeak-ng | 不生成 IPA 音标,其它功能照常;`demo.py` 无法合成演示音频 | 想要音标就装 |

**Windows 最省事的装法(会自动配好 PATH):**

```powershell
winget install Gyan.FFmpeg
winget install eSpeak-NG.eSpeak-NG
```

装完**必须关掉命令行窗口重新开一个**,PATH 才会生效。

**手动配 PATH(没有 winget 或想装绿色版时):**

1. 把解压出来的目录记牢,比如 ffmpeg 是 `C:\ffmpeg\bin`(这个目录里要能看到 `ffmpeg.exe`)
2. 按 `Win + S` 搜「环境变量」→ 打开「编辑系统环境变量」→ 点「环境变量」按钮
3. 在上半部分「用户变量」里选中 `Path` → 「编辑」→「新建」→ 粘贴那个目录 → 一路确定
4. **关掉所有命令行窗口,重新打开一个**,输入 `ffmpeg -version` 验证

**其实也可以完全不碰 PATH:** 程序会自己去几个常见安装位置找
(`C:\Program Files\eSpeak NG\`、`C:\ffmpeg\bin\`、winget 的 Links 目录、
scoop 的 shims 等)。另外 `pip install imageio-ffmpeg` 会装一个自带的 ffmpeg 二进制,
程序也认——这是最省事的一条路,一条 pip 命令解决,不用改任何系统设置。

跑 `python process.py` 时开头会打印环境自检,告诉你这两个到底找到没有。

### 2. 填 API Key

```bash
cp .env.example .env      # 然后编辑 .env,填入 DeepSeek 或 Kimi 的 key
```

### 3. 处理视频

```bash
python3 process.py 我的视频.mp4 --title "第1期 · 咖啡店点单"
python3 serve.py
```

## 四、成本

| 环节 | 花费 |
|---|---|
| 语音识别 | **0**(本机跑,模型首次自动下载) |
| IPA 音标 | **0**(本机 espeak-ng) |
| 单词发音 | **0**(浏览器自带朗读) |
| 难度/时长/语速 | **0**(纯计算) |
| 语义群切分 + 翻译 + 卡片 | 走 API,一期 5 分钟视频约几分钱 |

省钱的三个设计:

1. **结果按内容哈希缓存**,同一个视频重跑不会二次付费(`--no-cache` 可关闭);
2. 默认用 deepseek-chat(单价最低那档),`--llm kimi` 可切换;
3. 每次运行结束打印 token 用量和估算费用,心里有数。

只想要字幕不要卡片,加 `--no-cards`,费用再降一半左右。

## 四点五、刷视频时一键存进来

在 YouTube / TikTok / 抖音刷到想学的内容,**点一下书签栏就进队列**,不打断你刷视频。

### 装一次

```bash
python serve.py
```
打开 `http://localhost:8777/setup`,把页面上那个按钮拖到书签栏。拖一次就好。

### 以后怎么用

1. 在视频页面点一下书签 → 页面上冒出一个提示,链接已入队
2. 想跑的时候:`python worker.py`(或 `python worker.py --watch` 一直守着)
3. `python serve.py` 打开播放器学

刻意做成「先入队、后处理」:处理一个视频要几十秒到几分钟,
点书签那一下必须立刻返回,否则刷视频的手感就断了。

### 三个平台走三条不同的路

| 平台 | 做法 | 说明 |
|---|---|---|
| **YouTube** | **取官方字幕 + 嵌入官方播放器,不下载** | 跳过最慢的语音识别,不占磁盘。自动字幕在 json3 格式下自带词级时间戳,精度够用。嵌入是平台官方支持的用法 |
| TikTok | 下载音频 → 完整流水线 | 需要 yt-dlp;适配相对稳定 |
| 抖音 | 下载音频 → 完整流水线 | 需要 yt-dlp;适配不稳定,可能失败 |
| 其它网址 | 通用四策略 | 直链 / 播客订阅源 / 页面内地址 / HLS |

YouTube 那条路是这次最大的收益:一个 10 分钟的视频,取字幕几秒钟,
而跑语音识别要几分钟,还要先下载几十 MB。

### 手动方式(不用书签也行)

```bash
python fetch.py <网址>              # 先分析,看看里面有什么
python process.py --url <网址>      # 直接加工
python process.py --url <YouTube网址> --force-download   # 强制下载跑识别,而不是取字幕
```

### 几个前提

- `python serve.py` 得开着,书签才有地方送
- 浏览器建议 Chrome / Edge:它们把 `localhost` 当可信来源,HTTPS 页面也能访问本地服务。
  Safari 会拦,拦了书签会自动改为新开标签页兜底
- TikTok / 抖音需要你自行 `pip install yt-dlp`,本项目不捆绑它
- 书签里带一个本机令牌,防止任意网页往你的队列里塞东西;换机器要重新拖一次

### 合规

只取回公开可访问的内容,不绕过付费墙、登录态或 DRM。
目标平台的服务条款与内容版权由使用者自行负责——自用与对外分发是两件不同的事。
细节见 `docs/在线视频解析-探索笔记.md`。

## 五、常用参数

```
--title      这一期的标题
--llm        deepseek(默认)| kimi
--asr-model  tiny.en / base.en / small.en(默认)/ medium.en   越大越准越慢
--no-cards   只做字幕,跳过知识点卡片
--no-cache   不用缓存,强制重新调用模型
--keep-media 不复制视频进 library(省磁盘,但视频不能挪位置)
--force      这个网址已经做过也照样重做一遍
```

### 同一个视频只会解析一次

判重按「这是哪个视频」而不是按链接字符串。下面这些都会被认成同一期,
第二次投递会当场被拦下,不会重新花钱:

```
https://www.youtube.com/watch?v=abc12345678
https://www.youtube.com/watch?v=abc12345678&t=100s
https://youtu.be/abc12345678?si=xxxx
https://www.youtube.com/shorts/abc12345678
```

非 YouTube 的网址也会先剥掉 `utm_*`、末尾斜杠这类不影响内容的部分再比。
确实想重做同一个视频,加 `--force`。

机器慢就用 `--asr-model base.en`,追求准确度用 `medium.en`。

## 六、关于准确率(请如实告知使用者)

vlog 是自然口语,有背景音和口音,**语音识别准确率通常在 85-95%**,
语义群切分和翻译也会有瑕疵。这是这类技术当前的正常水平,不是没做好。

工具为此内置了校对线索:`data.json` 的 `review.low_confidence_words` 里
列出了识别把握较低的词,校对时只看这些就行,不必通读全文。
`review.dropped_cards` 记录了被判定为原文中不存在、已剔除的词条。

## 七、考级标签

默认由模型判断,大致准确。想要 100% 准确:把考纲词表放进 `wordlists/` 文件夹
(一个文件一个标签,文件名即标签名,每行一个词),重新处理即可。词表优先于模型。

## 八、目录结构

```
process.py            主流程:视频/网址 → data.json
fetch.py              解析一个网址,看看里面有什么
worker.py             处理收件箱队列
repair.py             就地修已生成的 data.json(不花 API 钱)
demo.py               生成演示内容(不需要 key)
serve.py              本地服务(支持 Range 请求,视频才能拖动)
library.html          素材库:按时长/作者排序,按作者看合集
player.html           播放器(单文件)
teco/
  llm.py              DeepSeek/Kimi 统一客户端 + 缓存 + 用量统计
  asr.py              语音识别(词级时间戳)
  segment.py          语义群切分 + 翻译     ← 核心
  cards.py            知识点抽取 + 回原文校验 ← 核心
  ipa.py              IPA 音标(本机)
  meta.py             难度/语速/建议时长/主题
  platforms.py        平台识别:决定走哪条路
  captions.py         YouTube 字幕获取与词级时间戳解析
  ingest.py           通用网址解析(直链/订阅源/页面/HLS)
  inbox.py            书签栏投递的队列
  library.py          素材库索引与「这个视频做过没有」
library/<期数>/       data.json + 视频 + 封面
wordlists/            可选:权威考纲词表
```

## 八点五、改了规则之后,老素材怎么跟上

`repair.py` 专门干这件事:凡是本机算得出来的,就地改掉,不重新调用模型。

```bash
python repair.py --merge      # 按当前标准重新合并过短的语义群
python repair.py --authors    # 回填作者(问一次 yt-dlp,不下载)
python repair.py --reindex    # 只重建 library/index.json
python repair.py --dry-run --merge   # 先看会改成什么样,不写文件
```

「过短」同时看词数和时长(默认少于 8 个词 **或** 短于 2.2 秒),因为光看词数
在快素材上等于没看:8 个词在 120 词/分是 4 秒,在 240 词/分只有 2 秒,一闪就过去了。
合并时会避开真实停顿——两段之间静音超过 0.65 秒,说明那里本来就该断开。

`--merge` 会改变段号,之前收藏的句子和播放进度会对不上,重新收藏即可;
原文件会留一份 `data.json.bak`。

## 九、这套东西还能干别的

流水线的内核是「**把非结构化的音视频,变成结构化的、可检索的专业记录**」。
换掉 `cards.py` 里的抽取提示词和输出模板,同一套骨架可以做:
会议录音 → 纪要与待办、上门服务录音 → 工作记录、播客 → 笔记、课程 → 讲义。

英语学习只是它的第一个应用。
